# Assignment Rubric

Use this rubric for every assignment.

## Score Levels

| Score | Meaning |
| --- | --- |
| 4 | Ready for supervised real repo work |
| 3 | Good, minor gaps |
| 2 | Understands pieces, needs more practice |
| 1 | Unsafe or unclear |

## Review Categories

### 1. Safety

- 4: Uses branches, no production secrets, no unsafe commands, identifies risk clearly.
- 3: Mostly safe, but misses one small precaution.
- 2: Needs reminders about secrets, DB safety, or production boundaries.
- 1: Performs or proposes risky production actions.

### 2. Codex Usage

- 4: Gives Codex clear context, asks for plans before edits, verifies output, challenges assumptions.
- 3: Uses Codex effectively but sometimes accepts answers too quickly.
- 2: Prompts are vague or evidence is thin.
- 1: Copies AI output without understanding or validation.

### 3. Technical Understanding

- 4: Explains architecture, data flow, and tradeoffs accurately.
- 3: Understands main flow but misses edge cases.
- 2: Can describe files but not how behavior connects.
- 1: Cannot explain what changed or why.

### 4. Verification

- 4: Runs relevant build, test, and manual checks; records evidence.
- 3: Runs basic checks but misses one useful validation.
- 2: Runs commands without interpreting results.
- 1: No meaningful validation.

### 5. GitHub Workflow

- 4: Clean branch, clear commits, readable PR, good review response.
- 3: Minor commit or PR clarity issues.
- 2: Messy commits or incomplete PR description.
- 1: Works directly on main or cannot show changes clearly.

## Passing Standard

Aqilah should average at least `3` across assignments 1-7 before starting the capstone.

For the capstone, she should score `4` in Safety and at least `3` in every other category.
